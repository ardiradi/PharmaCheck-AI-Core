## Meaningful checks

- Conservative anchored labels and aliases, immediate-next-line values, empty/missing fields, repeated identical values, conflicting candidates, unchanged OCR character errors, and unrelated substring false matches.
- A following recognized label with missing colon is not consumed as another field's value; values do not cross page boundaries.
- File/type limits, corrupt image/PDF, six-page PDF rejection, oversized image/PDF rejection before large rendering, and Pillow decompression-bomb classification.
- Isolated worker deadline, private stdout/stderr, bounded raw output, safe fixed failure codes, invalid reply rejection, and temporary-file cleanup on success and timeout.
- Local AppTest startup/button/raw-text/conflict/empty flows without Azure configuration/client, secrets access, or socket calls. One local AppTest uses real native JPEG OCR rather than a fake adapter result.
- Historical Azure configuration, field mapping, and sanitized diagnostic functions remain AST-identical; their startup/failure tests explicitly select the optional Azure mode. No genuine Azure action is performed by these tests.
- Existing runtime compatibility checks still pass with CORS/XSRF enabled and 30-second WebSocket timeout behavior.

Independent review confirmed PDF native-object lifetime handling and worker isolation, and found an oversized-image diagnostic mismatch. The fix maps Pillow's decompression-bomb exception to the explicit pixel-limit message; a valid 25 MP compressed image regression passed.

## Boundaries

Limits are 10 MiB input, five PDF pages, 12 megapixels per page, 15 seconds per native page recognition, 60 seconds per worker, and 200,000 raw characters. Linux adds a 2 GiB address-space ceiling per worker. There is no global concurrency ceiling; this remains a small prototype. A separate password-protected PDF fixture has not been tested.

The local Docker daemon was absent and was not started. The new Linux image, its actual bundled Tesseract version, and deployed local OCR remain unverified. Official PyPI has the required CPython 3.12 x64 manylinux tesserocr wheel; the Docker build requests binary wheels and distribution runtime packages. A Windows pass is not a Linux build/deployment result. No browser, HF deployment, Azure call, credential change, new account, activation, billing, or paid API action was taken in this source task.
